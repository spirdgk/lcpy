# Summary

Lcpy is an open-source python package for flexible, parametric, and modular dynamic Life Cycle 
Assessment (LCA) and Life Cycle Costing (LCC). It considers the investigated process as the main process
consisting of other sub-processes (Figure 1). Each sub-process includes inflows and outflows 
(sub-sub-processes) causing environmental impact and costs. Python dictionaries and lists are filled for
each sub-process that include 1) the names of the sub-sub-processes, 2) the amounts consumed, 3) the 
costs incurred, and 4) keys pointing to ecoinvent activities. A similar dictionary and list is filled 
for the main process. Lcpy provides functions to scale the unit impacts and costs of each sub-sub-process 
with the respective amount needed for the sub-process, calculating thus the unit impact and cost for 
each sub-process. This is scaled with the amount needed for the main process calculating the result. 
Once calculated, the main process can be used as a sub-process in a next modelling step. Lcpy is agnostic
to what the processes represent, how the amounts and costs are calculated, and what temporal resolution
is used for their calculation. This provides the flexibility to model different systems, include 
long-term projections or real-time data, and perform uncertainty analysis. Lcpy is uses the brightway 
software and a range of cython functions to allow fast calculations, while several functions for 
visualization and storing are available to allow for the interpretation of the results.

# Statement of need

LCA and LCC are well-established methods for assessing the environmental and economic sustainability of
products and systems. Despite the two methods sharing common underlying principles, current LCA software
development has paid low attention to the cost aspect. With the development of the brightway (bw) 
software [@Mutel_2017], which allowed flexible LCA calculations in python, several open-source packages 
promoted dynamic or prospective LCA. Premise [@Sacchi_2022] and pathways [@Sacchi_2024] allow modifying the ecoinvent 
database [@Wernet_2016], via the python package wurst [@Mutel_2017b], to construct prospective background databases 
according to the projections of integrated assessment models. The Temporalis software [@Cardellini_2018] proposed 
solving the dynamic inventory problem through graph traversal and convolution algorithms. On top of 
temporalis, the timex package [@Diepers_2025] allows the introduction of prospective background databases 
generated by premise. Several other tools are tackling dynamic LCA aspects (e.g.,  
dynCO2 [@Levasseur_2010], DyPLCA [@Pinge_2020], or the GREET model [@Wang_1999] which allows to input efficiency changes 
over time). In addition, several studies have suggested dynamic LCA methods without however providing the 
tools used [@Gkousis_2022; @Collinge_2013; @Beloin_Saint_Pierre_2017].

Open-source LCA software is rarely combined with LCC calculations missing on the synergies of the two 
methods. Also, access to temporal distributions for the background activities can be scarce, limiting 
the application of dynamic LCA. In addition, coupling the current dynamic LCA software with modular, 
parametric, and dynamic models requires deep knowledge of the bw software, while the integration with 
external simulation models can be difficult.

Lcpy proposes a simple process-based structure for flexible, parametric, and modular dynamic LCA and LCC. 
It aims to be used in parallel with the above-mentioned software towards easy implementation of dynamic 
sustainability analysis. It adopts a brute approach for the dynamic inventory construction by defining 
a time step (e.g., years or minutes for long- of short-term analysis) and populating python arrays with 
the amounts of sub-sub-processes associated with each sub-process. Arrays with the costs and revenues 
occurring due to the sub-sub-process are also populated for the LCC calculations. Lcpy suggests a 
structured way of modelling each sub-process and provides functions for conducting traditional LCA, 
semi-dynamic LCA (only dynamic inventory), fully-dynamic LCA (dynamic impact assessment), and LCC 
analysis. Functions to calculate techno-economic indicators such as Net Present Value (NPV), Levelized 
Cost of Electricity (LCOE), and Minimum Selling Price (MSP) are also provided if revenues are to be 
considered as well.

# Description

Lcpy consists of three modules, the calculators module that provides classes orchestrating the 
calculations, cython files providing calculation functions allowing fast multidimensional assessment, 
and the hvs module containing functions that control the flow of information and provide visualization 
and storage functionalities.

First, a few parameters need to be set such as the number of scenarios, timeframe and time step, and the
inclusion of construction activities. A model, is then defined to estimate the amounts of 
sub-sub-processes required for each sub-process and the amount of each sub-process feeding the main 
process. This information can be provided in scalar values or 2-D arrays representing scenarios and 
time steps. 

The LCC and LCA calculations are independent and can be performed individually. It is recommended to 
build the parametric model such that it can be used both in the LCA and LCC calculations 
(e.g., calculate the amounts of inflows and outflows for LCA and then multiply them by the price for LCC).

For the LCA calculations the bw 2.0 software is employed. To avoid conflicting dependencies between bw 
and other packages, lcpy requires a bw environment to be installed in another folder, with a brightway 
project, an ecoinvent copy, an own-defined bw database, and a biosphere database. It is recommended to 
use the Activity Browser (AB) [@Steubing_2020] or directly bw to set this up. The above-mentioned information is 
given via a dictionary to an mpLCAer instance, which is the class handling bw calculations in lcpy. The
names of the impact assessment methods, also extracted from AB or bw, need also to be defined.

Each sub-process in lcpy is modelled with a dictionary and a list. For the LCA, the dictionary holds 
the names of the sub-sub-process (keys), and unique ids pointing to the respective activity in the 
bw project (values). The list holds scalar values or numpy arrays with the amount of each 
sub-sub-process needed for the sub-process (exchange amounts). For the LCC, the dictionary holds as 
keys the names of the sub-sub-process, and as values empty strings. The list holds the cost caused by 
each sub-sub-process included in the sub-process. If revenues are to be provided and examined 
separately then a dictionary and a list for the revenues need also to be provided to allow for using 
lcpy’s function for NPV, MSP, and LCOE calculation. A dictionary and a list are also constructed for 
the main process getting input from the sub-processes (Figure 1).

Once these dictionaries are set, they need to be gathered in a list and next lcpy functions are used to 
exploit this information. Functions from the hvs module transform the information to the appropriate 
format to be fed to classes from the calculators module. These classes use cython functions for speed, 
to scale the unit impacts and costs of each sub-sub-process with the actual amounts consumed. The 
scaling is done twice, 1) for scaling the unit impacts/costs of the sub-sub-processes with the amounts 
per sub-process and 2) for scaling the unit impacts/costs of the sub-processes with the amounts for the 
main process. The results are provided in python dictionaries and lists allowing for examination and 
visualization. Depending on the modelling choices the results can be calculated per functional unit or 
as absolute numbers. The calculated main process can be used as a building block (sub-process) in 
another main process, without using brightway, since its impact is precalculated. In a similar way 
processes not included in the bw project can be included in lcpy (e.g., processes coming from another 
database).

Lcpy aims to provide a simple way into dynamic LCA and LCC and their integration with other 
computational methods. All calculations are made in python using an object-oriented approach, with 
minimum package requirements to allow for integration with other packages. The technical documentation 
and notebook examples explain technicalities associated with the actual application of LCA and LCC in 
lcpy describing for example the functions used and how to load dynamic characterization factors.
